## 3. MVP 范围

### 3.1 带来源的专业知识问答

- 知识范围仅包含两篇经过确认的开放获取论文。
- 用户输入专业问题后，系统先从本地论文中检索相关原文，再把检索证据交给 DeepSeek 组织回答。
- 页面同时显示资料编号、论文题名、PDF 页码、原文片段和相关度。
- 回答中的关键结论必须使用 `[资料编号, p.页码]` 格式引用。
- 没有检索证据时，本地程序直接拒答，不调用模型凭记忆补充。
- 模型引用了本次检索结果以外的来源，或回答完全没有引用时，Python 校验会拒绝展示该回答。

### 3.2 CSV 指标、图表和异常分析

- 当前只支持一套固定模板：GBK 编码、12 列、365 行日尺度数据，日序号必须为连续整数 1—365。
- 校验内容包括列名与顺序、行数、空值、非数值、日序号和比例取值范围。
- Python 根据 CSV 计算电量、出力占比、功率平衡残差等指标。
- 固定生成五组 matplotlib 图表。
- 按五类透明规则识别异常：功率不守恒、供电不足、高弃风光、高弃水、计划执行偏差较大。
- 功率平衡核算公式为：水电出力 + 风光出力 + 负荷 × 出力不足率 − 负荷。
- MVP 阈值为：功率平衡绝对残差大于 0.01 MW；弃风光率、弃水率或水量偏差率绝对值大于 10%。这些是本项目确认的分析规则，不是论文结论或行业强制标准。
- 对 CSV 已经给出的弃风光率、出力不足率、弃水率和水量偏差率不重新构造模型计算，而是按已确认的业务规则进行核验和异常标记。

### 3.3 结构化分析报告

- 页面内预览报告，并支持下载 Markdown 文件。
- 报告固定包含数据概况、关键指标、图表解读、异常清单、资料依据和结论边界。
- 所有数值、单位、异常日期、阈值和来源由 Python 写入。
- DeepSeek 仅生成简短的定性图表解读。
- 模型生成的报告解读不得包含阿拉伯数字、全角数字或百分号；检测到这些内容时程序拒绝生成报告，防止模型修改 Python 计算结果。

## 4. 完整用户流程

1. 用户在本地启动 Streamlit 服务，并在浏览器打开产品页面。
2. 用户上传固定模板 CSV。
3. 系统先校验数据格式，校验通过后才继续分析。
4. Python 计算指标、核算功率平衡、生成图表并输出异常清单。
5. 用户可以输入专业问题；系统先检索论文证据，再调用 DeepSeek 生成带引用回答。
6. 系统把 Python 结构化结果和检索证据用于报告生成；模型只补充无数字的定性解读。
7. 用户在页面预览报告并下载 Markdown 文件。

## 5. AI 产品与技术方案

### 5.1 职责分工

| 内容 | 负责模块 | 设计原因 |
| --- | --- | --- |
| CSV 校验、指标和异常 | Python | 需要精确、稳定、可复核 |
| 专业资料查找 | 本地检索 | 限定知识边界并保留可追溯来源 |
| 问答和定性表达 | DeepSeek | 将证据和结构化结果组织为自然语言 |
| 引用、数字和报告结构校验 | Python | 限制模型自由度，降低来源或数字失真风险 |

### 5.2 最小 RAG 实现

- 使用 `pypdf` 按页提取两篇论文文本。
- 将文本切分为约 800 字符、120 字符重叠的文本块。
- 使用字符级 TF-IDF（2—4 gram）表示问题和文本块。
- 使用余弦相似度排序并过滤低相关结果。
- 检索结果封装为 Evidence，包括资料编号、题名、PDF 页码、原文片段和相关度。
- 该方案没有使用向量数据库、Embedding API、重排序模型或 Agent。选择原因是 MVP 知识量小，优先保证本地可运行、容易解释和来源可追溯。

### 5.3 大模型调用与安全边界

- 模型服务：DeepSeek API。
- 当前代码中的模型：`deepseek-v4-flash`，关闭思考模式。
- API Key 只从当前计算机的环境变量 `DEEPSEEK_API_KEY` 读取。
- Key 不写入代码、项目文档、截图或 Git。
- 新开终端后需要重新临时设置 Key；关闭终端后临时环境变量消失。
- 未设置 Key 时，CSV 校验、Python 分析、图表、异常清单和本地证据检索仍可使用；AI 回答和 AI 报告解读不可用。
- 问答阶段发送用户问题与检索证据；报告阶段发送结构化指标、异常和证据。程序没有把原始 CSV 文件直接交给模型自行分析。

## 8. 真实数据与验收结果

### 8.1 真实 CSV 分析

- 用户明确批准使用一份非保密 CSV 进行本地验收。
- CSV 校验通过，共 365 行。
- 最大功率平衡绝对残差的原始计算值约为 3.67×10⁻⁷ MW；页面按六位小数显示为 `0.000000 MW`。
- 功率不守恒 0 天。
- 供电不足 8 天。
- 高弃风光 15 天。
- 高弃水 13 天。
- 计划执行偏差较大 30 天。
- 五类规则合计产生 66 条异常记录；同一天可以触发多条不同规则。
- 年负荷电量 44780.984 GWh，年水电电量 38016.177 GWh，年风光上网电量 6764.472 GWh。
- 水电占比 84.89%，风光占比 15.11%，供电不足电量 0.335820 GWh。
- 五组图表和异常清单经过人工查看，均正常显示。

### 8.3 真实报告

## 9. 已确认的产品决策与取舍

| 决策 | 取舍 |
| --- | --- |
| 固定 CSV 模板 | 减少字段映射和兼容性复杂度，优先打通核心分析流程 |
| Python 负责数字，模型负责语言 | 牺牲模型自由度，换取数值可复核性 |
| TF-IDF 而非向量数据库 | 适合两篇论文的小知识库，部署简单且容易现场解释 |
| 本地应用 + 云端模型 API | 数据处理和知识库保留在本地，同时使用外部模型生成能力 |
| 固定异常规则 | 结果透明可解释，但尚未形成可配置规则平台 |
| Markdown 报告 | 生成和下载简单，但没有实现 Word/PDF 排版 |
| 两篇公开论文 | 控制来源质量和合法性，但知识覆盖面有限 |
| 单页 Streamlit | 适合 MVP 和现场演示，不代表生产级前端架构 |

## 11. 当前限制与禁止虚构项

### 当前限制

- 只支持一套固定 GBK CSV 模板和 365 行日尺度数据。
- 知识库只有两篇公开论文，不包含正式调度规程全文。
- 检索是 TF-IDF，不是语义 Embedding，也没有向量数据库。
- 没有实现 Agent、多工具自主规划、长期记忆或多轮任务执行。
- 没有实现用户系统、权限控制、在线部署、数据库或多人协作。
- 产品通过 PowerShell 启动本地 Streamlit 服务，浏览器只负责访问界面。
- DeepSeek API 需要网络和临时 API Key；没有完成费用统计或长期稳定性测试。
- 异常阈值是 MVP 规则，不应描述为行业标准。
- 当前 Git 历史只在本地，没有上传到 GitHub，也没有线上仓库链接。

### 禁止虚构

简历 AI 不得增加以下未经验证的信息：

- 用户数、付费用户、企业客户或真实业务上线；
- 节省工时比例、效率提升比例或成本下降比例；
- RAG 准确率、召回率、幻觉率或模型评分；
- API 平均延迟、平均费用、并发量或可用性；
- 获奖、专利、论文成果或导师/企业评价；
- 独立完成全部代码、生产部署或团队管理经历；
- 使用 LangChain、LlamaIndex、向量数据库、Agent 框架等本项目没有使用的技术。
