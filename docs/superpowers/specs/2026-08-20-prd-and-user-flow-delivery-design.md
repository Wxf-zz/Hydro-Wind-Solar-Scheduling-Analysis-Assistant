# 水风光调度智能分析助手：PRD 与用户流程图交付设计

## 1. 目标

在项目根目录生成两份可独立阅读的产品文档：

- `产品需求文档PRD.md`
- `用户流程图.md`

两份文档均面向“水风光调度智能分析助手”，不使用与本项目无关的求职助手流程。

## 2. PRD 结构

PRD 固定包含以下十个章节：

1. 项目背景
2. 用户画像
3. 用户痛点
4. 产品目标
5. 用户流程
6. 功能架构
7. 核心功能需求
8. 非功能需求
9. 产品指标
10. 后续迭代

内容只使用当前代码、README、产品设计规格、知识库清单和真实验收记录中能够核对的事实。产品指标需要区分目标值、已验证结果和暂未验证指标。

## 3. 用户流程图结构

流程图使用 Mermaid，主流程为：

```text
启动本地应用
→ 上传调度结果 CSV
→ CSV 校验
→ Python 计算指标并核算功率平衡
→ 生成图表和异常清单
→ 输入专业问题
→ 检索论文证据
→ DeepSeek 生成带引用回答
→ 生成结构化报告
→ 预览并下载 Markdown
```

流程图同时表达四个真实异常分支：

- CSV 校验失败：显示明确错误，用户修改后重新上传；
- 未配置 API Key：确定性分析和本地检索仍可用，AI 生成不可用；
- 知识库无充分证据：系统拒答，不让模型凭记忆补充；
- AI 输出未通过引用或数字边界校验：不展示不合格内容，并提示错误。

流程图下方附节点说明，避免只看图时误解 Python、本地检索和 DeepSeek 的职责。

## 4. 事实与表述边界

- 不虚构用户数量、商业收入、效率提升比例、RAG 准确率、API 成本或生产环境表现。
- 明确当前只支持固定 GBK、12 列、365 行的 CSV 模板。
- 明确知识库当前只有两篇已批准公开论文。
- 明确异常阈值属于 MVP 规则，不冒充行业强制标准。
- 明确 Python 负责数值、异常和报告结构，DeepSeek 负责受约束的自然语言生成。
- 将三次人工端到端运行均小于 180 秒、26 项自动化测试通过等事实标为已验证结果，不推导平均耗时或性能提升。

## 5. 验收标准

- 两个文件均保存在 `D:\agent` 根目录，使用 UTF-8 Markdown。
- PRD 十个指定章节齐全，功能范围与当前 MVP 一致。
- Mermaid 语法包含主流程、判断节点和异常回路。
- 文档之间的功能名称、指标和边界保持一致。
- 不包含 API Key、保密 CSV 内容或未经验证的结论。
- Markdown 无占位符、断裂标题或明显格式错误。
