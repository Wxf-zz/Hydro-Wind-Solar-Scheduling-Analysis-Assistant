# 水风光调度智能分析助手：MVP 产品设计规格

- 日期：2026-08-09
- 状态：已批准
- 阶段：第一阶段——用户、痛点、场景、范围与成功指标

## 1. 项目目标

完成一个可在个人电脑本地启动、可用于求职现场演示的水风光调度智能分析助手。产品不替代优化调度模型，而是处理模型运行结束后的结果分析、资料查证和汇报材料整理。

## 2. 用户与问题

### 2.1 核心用户

水风光调度领域的研究生或科研人员。

### 2.2 核心痛点

研究者完成模型计算后，仍需重复编写分析脚本、绘制图表、逐项检查约束或异常，并将结果整理为汇报材料。这个过程耗时，且容易遗漏异常。

### 2.3 核心场景

组会或阶段汇报前，研究者需要快速把一份调度结果整理成可解释的指标、图表、异常清单和文字结论。

### 2.4 用户任务

当调度模型已经产生一份结果 CSV，而用户准备组会或阶段汇报时，用户希望快速完成结果检查和材料整理，以便把时间用于解释结论，而不是重复处理数据。

## 3. 价值主张

用户上传符合模板的调度结果 CSV 后，系统自动计算关键指标、生成图表、按专业规则识别异常，并结合可追溯的公开资料生成结构化分析报告，目标是帮助用户在 3 分钟内完成一轮结果整理。

产品主线为：上传调度结果 → 看懂关键表现 → 定位异常 → 查阅依据 → 生成报告。

## 4. 方案比较与选择

### 4.1 方案 A：分析任务流

上传 CSV 后依次完成校验、分析、异常识别、资料检索和报告生成。该方案紧扣核心痛点，三个功能能形成一条适合现场演示的闭环。

### 4.2 方案 B：三个独立工具

把知识问答、结果分析和报告生成做成并列页面。结构直观，但用户需要自行衔接结果，产品容易呈现为工具集合。

### 4.3 方案 C：对话式智能体

通过聊天让 Agent 自动调用检索和分析工具。AI 产品感较强，但流程不透明、开发复杂度高，现场演示风险也更高。

### 4.4 决策

MVP 选择方案 A。知识问答和报告生成围绕 CSV 分析结果提供支撑，不建设通用 Agent。

## 5. MVP 功能范围

### 5.1 调度结果分析

- 只接受一套固定格式的 CSV。
- 上传后检查必需字段、数据类型、空值和时间顺序。
- 只有校验通过的数据才能进入分析。
- 指标由 Python 确定性计算，不交给大模型计算。
- 根据数据生成预先定义的分析图表。
- 使用固定专业规则识别异常。
- 每条异常显示时间、实际值、规则阈值和触发原因。

具体字段、单位、指标公式和规则阈值必须来自用户后续明确授权的 CSV 及其专业定义。该材料确认是进入实现计划的前置条件；在此之前不作推断。

### 5.2 专业知识问答

- 只检索演示前导入的少量公开论文、报告和调度规则。
- 回答必须展示资料名称及页码、章节或其他可定位信息。
- 当前知识库没有依据时，明确告知用户未找到依据。
- MVP 不联网搜索，也不支持运行时上传任意 PDF。

### 5.3 结构化报告

- 报告输入只包括通过校验的 Python 计算结果、规则识别结果和检索证据。
- 报告包含数据概况、关键指标、图表解读、异常清单、资料依据和总结。
- 报告在页面内预览，并可下载为 Markdown 文件。
- 大模型负责组织语言，不重新计算或修改数值，不在证据不足时补写事实。

## 6. 用户主流程

1. 用户查看 CSV 模板要求并上传文件。
2. 系统校验 CSV；不合格时停止并指出具体问题。
3. Python 计算指标、生成图表并执行异常规则。
4. 页面展示分析概览和异常清单。
5. 系统根据分析主题检索相关公开资料，并展示证据片段及出处。
6. 用户可继续提出专业问题，回答附带来源。
7. 用户请求生成报告。
8. 大模型根据计算结果和检索证据组织报告文字。
9. 用户预览并下载 Markdown 报告。

## 7. 系统边界与数据流

本阶段只确定职责边界，不选择具体框架或第三方库。

- 本地界面：接收 CSV、展示分析结果、承载问答和报告下载。
- CSV 校验与分析模块：验证输入契约并输出结构化指标与图表数据。
- 异常规则模块：根据明确阈值输出可解释的规则触发记录。
- 本地检索模块：从预先整理的公开资料中返回证据片段和来源定位。
- 云端大模型：基于检索证据回答问题，并基于结构化分析结果组织报告。
- 报告组装模块：限制模型输入，校验报告所引用的数值和来源，并输出 Markdown。

核心数据流为：CSV → 校验 → 确定性分析 → 规则异常 → 证据检索 → 受约束的大模型生成 → Markdown 报告。

CSV、分析中间结果和知识库保留在本地。云端大模型只接收完成当前问答或报告所需的最小上下文。API 密钥只允许通过环境变量提供。

## 8. 可信反馈与错误处理

- CSV 不合格：显示具体缺失字段、错误数据类型、空值位置或时间顺序问题，不继续分析。
- 没有规则触发：显示“未发现符合当前规则的异常”，不宣称结果绝对正常。
- 知识库证据不足：明确说明当前资料未找到依据，不生成无来源结论。
- 云端 API 失败：保留本地指标、图表和异常结果，提示问答或报告暂不可用。
- 数值一致性：报告只能引用结构化计算结果，不能让大模型生成或修正指标值。
- 来源一致性：报告和问答中的资料结论必须链接到实际检索到的来源记录。

## 9. 明确不做

- 多调度方案对比。
- 优化求解、重新调度或决策推荐。
- 任意格式 CSV 自动识别和字段映射。
- 通用 Agent、自主规划或多工具编排。
- 互联网实时搜索。
- 用户账户、权限管理或云端数据存储。
- Word、PDF 或 PPT 导出。
- 完全离线的大模型部署。

## 10. 成功指标与验证方法

以下内容是待实现后验证的目标，不代表现有测试结果。

### 10.1 首要成功指标

在目标演示电脑和正常网络下，使用约定的非保密 CSV，从选择文件开始，到 Markdown 报告可下载为止，端到端耗时不超过 3 分钟。

验证方法：在正式演示路径上实际计时，记录开始时间、报告可下载时间和总耗时。

### 10.2 质量底线

| 维度 | 验收目标 | 验证方法 |
| --- | --- | --- |
| CSV 校验 | 已设计的错误样例全部被阻止，并显示具体原因 | 逐个上传字段缺失、类型错误、含空值和时间乱序的文件 |
| 指标计算 | 测试数据的结果与人工核对结果一致 | 保存人工计算基准，逐项对比 |
| 异常识别 | 规则触发结果与人工核对清单一致 | 对比异常时间、数值、阈值和原因 |
| 来源可信 | 有依据的回答显示来源；无依据的问题明确拒绝补写 | 使用有答案和无答案两组问题测试 |
| 报告一致 | 报告数值与页面计算结果一致 | 抽取报告数值并与结构化结果逐项核对 |
| 演示稳定 | 完整主流程连续运行 3 次，无阻塞性错误 | 在目标演示环境记录三次端到端结果 |

## 11. 主要风险与控制方式

- 输入数据定义不清：实现前以获准 CSV 固定字段、单位和时间粒度。
- 专业阈值依据不足：每条规则记录专业定义或公开资料依据，不凭经验猜测。
- 大模型生成无依据结论：只提供检索证据与结构化结果，证据不足时拒绝生成。
- 网络或 API 不稳定：本地分析不依赖大模型；云端失败时保留已有结果并明确提示。
- 求职演示范围失控：严格遵守非目标清单，先证明单文件分析闭环。
- 数据或密钥泄露：只使用明确授权的非保密材料，密钥仅通过环境变量读取。
